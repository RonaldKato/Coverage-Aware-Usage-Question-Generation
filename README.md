# CA-UQG: Coverage-Aware Usage Question Generation
<img width="100%" height="221" alt="Screenshot 2026-09-15 at 23 11 49" src="https://github.com/user-attachments/assets/c833d008-2375-4d25-9942-fa9a15048153" />

Companion code for the paper *"Coverage-Aware Usage Question Generation:
Closing the Recall and Diversity Gap in Conversational Recommender
Systems"*, an extension of Kostric, Balog & Radlinski (2024), *"Generating
Usage-related Questions for Preference Elicitation in Conversational
Recommender Systems"* (ACM TORS).

## What this is
The original paper flags an open limitation: its pipeline optimizes for
*precision* of generated usage questions but does not measure or optimize
*recall* (coverage of the full space of possible item uses) or *diversity*.
This repository implements and evaluates a drop-in extension pipeline,
**CA-UQG**, that adds:

1. **Broadened candidate extraction** (`src/extraction.py`) — seven
   regex patterns (P1–P7) instead of the original single "for + gerund"
   rule (P1).
2. **Unsupervised usage-taxonomy induction** (`src/clustering.py`) —
   per-category KMeans over sentence embeddings, used as a reference for
   measuring coverage.
3. **Coverage-aware selection** (`src/selection.py`) — Maximal Marginal
   Relevance (MMR) selection under a fixed question-generation budget,
   contrasted with frequency-based selection (implicit in the original
   pipeline) and a cluster-stratified alternative.
4. **Three coverage/diversity metrics** (`src/metrics.py`) — Facet
   Recall, Tail Coverage (inverse-frequency weighted recall), and the
   label-free Vendi Diversity Score.

## Why a synthetic corpus?
The original Amazon review corpus (Ni et al., 2019) is not redistributable
and is not reachable from this offline environment. `src/data_generation.py`
builds a structurally faithful substitute: a hand-authored usage-facet
taxonomy per category (`data/taxonomy/*.json`, 10 facets × 12 categories)
expanded into review-like sentences via a template bank covering seven
syntactic realizations of usage statements. Because the *true* facet of
every sentence is known by construction, we can measure recall/coverage
*exactly*, which is not possible on unlabeled real review data. Every
module has a clearly marked swap point (e.g., replace `SentenceEmbedder`
with a `sentence-transformers` encoder, replace the corpus loader with a
real Amazon-reviews loader) to move from this reproducible demo to a
production corpus without touching the pipeline logic.

## Running everything

```bash
pip install -r requirements.txt
cd src
python data_generation.py      # writes data/synthetic_reviews.jsonl (+ taxonomy)
python extraction.py           # sanity-check candidate counts
python run_experiment.py       # writes tables/*.csv, data/per_category_budget8.csv
python pipeline.py             # runs the instrumented Stage/Pipeline, writes
                                #   data/pipeline_manifest.json,
                                #   tables/table5_pipeline_manifest.csv,
                                #   tables/table6_funnel.csv
python make_figures.py         # writes figures/*.png (10 figures, incl. the
                                #   object schema, annotated extraction, cluster
                                #   confusion matrix, labeled usage-space map,
                                #   and pipeline funnel diagrams)
```

All numbers and figures reported in the paper are regenerated by this
five-command sequence (seeded, deterministic).

## Repository layout
```
src/
  data_generation.py   synthetic corpus + usage-facet taxonomy generator
  extraction.py        baseline (P1) vs broadened (P1-P7) candidate extraction
  embeddings.py         TF-IDF + SVD sentence embedder
  clustering.py         unsupervised usage-taxonomy induction (KMeans)
  selection.py           frequency / MMR / cluster-stratified selection
  question_gen.py        template question generation + N/A rule filter
  metrics.py              Facet Recall, Tail Coverage, Vendi Diversity Score
  schema.py               typed dataclasses for every object in the pipeline
  pipeline.py             instrumented Stage/Pipeline runner + execution manifest
  run_experiment.py       orchestrates the full experiment grid (results tables)
  make_figures.py         renders all paper figures (10 figures)
data/
  taxonomy/*.json         gold usage-facet taxonomy per category (12 files)
  synthetic_reviews.jsonl generated corpus (667 sentences)
  selected_questions_sample.csv   qualitative examples per config
  per_category_budget8.csv        per-category metric breakdown

```

## Honesty / scope note
This is an independently produced research extension exercise. 
Numbers are computed on the synthetic corpus described
above; see the paper's Limitations section for what would need to change
(real review corpus, learned embeddings, neural question generation,
human evaluation) before these findings could be claimed on the original
task.
